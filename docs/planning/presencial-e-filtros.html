Plano de expansão

Presencial e nova experiência de filtros

Documento de alinhamento para levar o bloco Disciplinas EaD UEMS além da modalidade a distância, sem importar regras que só existem no EaD e sem poluir a interface com filtros que nem sempre fazem sentido.

UX tranquila Categoria como fonte principal Shortname não confiável Filtros em duas camadas

1. Problema

A implementação atual foi desenhada para o EaD, onde existe mais padronização: categorias mais previsíveis, cronograma da disciplina com ead_inicio/ead_final, e o conceito de Oferta/Reoferta. No Presencial, esses critérios não se sustentam.

O que o EaD tem hoje

  • Categoria Distância como marco de modalidade.
  • Curso e turma extraídos de uma árvore relativamente estável.
  • Cronograma gerido pela UEMS Virtual.
  • Datas de status baseadas em ead_inicio/ead_final.
  • Conceito de Oferta e Reoferta.

O que muda no Presencial

  • O shortname pode ter código gerado, mas não é garantido.
  • Salas manuais podem não seguir sigla correta.
  • A única fonte consistente é a categoria.
  • Não há cronograma da UEMS Virtual.
  • Datas vêm do sistema acadêmico via script Python + webservice Moodle.
  • Não existe Reoferta como categoria funcional do bloco.
Decisão de domínio: Presencial não deve reaproveitar cegamente filtros, status e rótulos do EaD. A expansão precisa ser por modalidade, com regras próprias e interface adaptativa.

3. Modelo de filtros em duas camadas

Para manter a interface relaxante, os filtros devem sair do modelo “tudo sempre visível”. A tela deve exibir apenas os controles estruturantes e esconder os filtros específicos atrás de um botão discreto.

1. Visão Aluno, Tutor, Docente ou Administrador.
2. Nível Graduação ou Pós-Graduação.
3. Modalidade/Formato Distância ou Presencial.
4. Mais filtros Abre filtros dependentes do nível e da modalidade.
Decisão de UX: Visão, Nível e Modalidade são filtros principais. Curso, turma, tipo, unidade, série e ano ficam em Mais filtros.
Contexto Filtros principais Mais filtros Não mostrar
Distância Visão, Nível, Modalidade Curso, Turma, Tipo Unidade/Cidade, Série, Ano
Presencial Visão, Nível, Modalidade Unidade/Cidade, Curso, Série quando existir, Ano quando existir Tipo, Oferta, Reoferta

4. Comportamento esperado da UI

Estado inicial limpo

  • Mostrar o alternador de visão somente quando houver mais de uma perspectiva.
  • Mostrar Nível e Modalidade quando houver mais de uma opção relevante.
  • Manter “Mais filtros” recolhido por padrão.
  • Botão de limpar filtros permanece pequeno e discreto.

Mais filtros

  • Abre/fecha por clique.
  • Conteúdo muda conforme Nível + Modalidade.
  • Não exibe filtro sem opções úteis.
  • Em mobile, deve empilhar sem overflow horizontal.

Filtros dependentes

  • Escolher Nível reduz Modalidades, cursos e demais filtros.
  • Escolher Modalidade troca o conjunto de filtros avançados.
  • Escolhas inválidas são limpas automaticamente.
  • Contadores das abas continuam atualizados.

Sem ruído

  • Não mostrar “Desconhecido” como filtro se isso gerar ansiedade.
  • Preferir omitir filtros incompletos.
  • Usar supertítulo parcial quando categoria estiver incompleta.
  • Não misturar conceitos do EaD no Presencial.

5. Datas e status por modalidade

Modalidade Fonte de datas Status Sem data
Distância ead_inicio + ead_final Abertas, Em breve, Encerradas com base no cronograma EaD. Tutor/Docente/Admin veem quando cronograma está ausente/incompleto e janela Moodle cruza o semestre vigente.
Presencial course.startdate + course.enddate, alimentados pelo sistema acadêmico. Abertas, Em breve, Encerradas com base na janela Moodle do curso. Precisa decisão: exibir só para staff/admin ou também para aluno quando a categoria indicar vínculo vigente.
Ponto pendente: definir a regra de “Sem data” no Presencial. Como as datas vêm do sistema acadêmico, ausência de data pode indicar problema de integração, sala manual, ou curso fora do fluxo automatizado.

6. Decisões propostas

  1. Categoria é fonte primária para modalidade, unidade, curso, série e ano no Presencial.
  2. Shortname é apenas auxiliar, nunca critério obrigatório para Presencial.
  3. Tipo/Oferta/Reoferta não existe no Presencial e não deve aparecer nessa modalidade.
  4. Datas do Presencial vêm da janela Moodle, não do cronograma EaD.
  5. Filtros devem ter duas camadas: principais visíveis e “Mais filtros” recolhido.
  6. Filtros avançados são governados por Nível + Modalidade.
  7. Presencial deve entrar atrás de configuração inicialmente, para homologar sem impactar o uso EaD.

8. Perguntas para fechar antes de implementar

  1. Presencial deve aparecer junto com EaD na mesma listagem, ou a Modalidade deve funcionar como filtro principal obrigatório?
  2. Quando houver apenas uma modalidade para o usuário, escondemos o filtro Modalidade?
  3. Aluno presencial pode ver sala sem course.startdate/course.enddate?
  4. Para Presencial, “Ano” deve ser filtro quando existir categoria de ano ou pode ser inferido da data de início?
  5. O painel “Mais filtros” deve lembrar estado aberto/fechado no navegador?
  6. Presencial entra primeiro só para Admin/Docente/Tutor ou já para Aluno?
